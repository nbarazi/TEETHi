# Sync the API contract

`docs/api/openapi.json` is the shared contract between `TEETHi-Backend` and its three clients. It is generated by Scramble from the backend code and never hand-edited (docs rule 4).

All paths below are relative to the workspace root, `D:\Projects\TEETHi Project`. `php` on PATH is a 0-byte stub, so always use Herd's binary:

```bash
PHP=/c/Users/ASUS/.config/herd-lite/bin/php.exe
```

## 1. Export the spec

The export boots the app and needs the backend database (the `MySQL80` Windows service). If the export fails to connect, tell the user to start MySQL. Don't try to change the DB config.

```bash
cd TEETHi-Backend && $PHP artisan scramble:export --path=../docs/api/openapi.json
```

## 2. Report what changed

```bash
git diff --stat -- docs/api/openapi.json
```

If nothing changed, say so and skip to step 4.

Otherwise, summarize the change at the level a client developer needs. Compare the committed spec with the new one, e.g. using `git show HEAD:docs/api/openapi.json` and Node:
- added and removed paths and methods
- changed request bodies (new or removed or renamed fields, required changes)
- changed response schemas and enum values (e.g. under `components.schemas`)

Ignore pure reordering or description-only changes. Mention them in one line at most.

## 3. Check the client plans cover it

For every changed endpoint, search the plans that document it:

```bash
grep -n "<path>" docs/plans/*.md
```

- Admin endpoints (`/admin/*`) are in `ADMIN_DASHBOARD_FRONTEND_PLAN.md`.
- `/patient/*` endpoints are in `PATIENT_APP_FRONTEND_PLAN.md`.
- `/doctor/*` endpoints are in `DENTIST_APP_FRONTEND_PLAN.md`.
- Shared endpoints (auth, `/me`, `/enums`, notifications, cities) can be in several plans.
- Backend-side detail lives in `IMPLEMENTATION_PLAN.md`.

List each plan section that now disagrees with the spec. Docs rule 3 says a contract change updates every affected plan in the same root commit. Propose the edits, but don't make them unless the user asked you to.

Also check the client code that parses each changed response, e.g. the Dart `fromJson`/mappers under `lib/features/**/data/` and the Angular models in `TEETHi-Frontend/src/app/**/*.model.ts`. Flag any that will break or silently drop a field.

## 4. Run the contract tests

The Dentist app has live contract tests that call every repository through the real `ApiClient`. They need the backend running on port 8000 with seed data. Check that first:

```bash
curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8000/api/v1/cities
```

If that doesn't return 200, check what owns the port before acting. Another project's server (`D:\Projects\Alwataniya-Backend`) sometimes holds 8000. It answers with a Laravel HTML error page instead of JSON:

```bash
netstat -ano | grep ':8000 ' | grep LISTEN   # then: wmic process where processid=<pid> get commandline
```

- If nothing is listening, start the `backend` config from `.claude/launch.json` with `preview_start`. Don't start it with Bash.
- If another project holds 8000, don't kill it. Serve TEETHi on 8001 instead (`artisan serve --port=8001`, as a launch.json entry), and pass `--dart-define=API_BASE_URL=http://127.0.0.1:8001/api/v1` below.

Then run:

```bash
cd TEETHI-Dentist-App && flutter test test/contract --dart-define=LIVE_BACKEND=true
```

The Patient app has no live contract suite. Its mapper tests (e.g. `test/features/timezone_contract_test.dart`) run offline:

```bash
cd TEETHi-Patient-App && flutter test
```

Report pass and fail counts exactly as printed. Don't round them or guess.

## 5. Finish

Don't commit unless the user asks. If they do, commit `docs/api/openapi.json` together with any plan edits in the root repo. Name the backend commit in the message, e.g. `Refresh the API spec (TEETHi-Backend 91a92ce)`, and end it with the session's attribution trailer.
